## How to run

### Step 1 — decode images (once per presentation)
```powershell
python step1_decode/decode_images.py
```

### Step 2 — generate layout (run as many times as you want)
```powershell
# Test one model with one prompt
python step2_layout_gen/run_model.py --model qwen --prompt v3_iaa

# Test another combination
python step2_layout_gen/run_model.py --model llava --prompt v2_semantic

# Quick test on 2 slides only
python step2_layout_gen/run_model.py --model qwen --prompt v1_basic --slides 1,2
```

Each run creates a new file in `outputs/` — nothing is overwritten.

### Step 3 — visualize
Open `step3_viewer/viewer.html` in browser → Load JSON → pick any output file → ← →

## How to create a new prompt version

1. Copy `prompts/v4_multimodal.py` to `prompts/v5_myidea.py`
2. Change `PROMPT_ID = "v5_myidea"`
3. Rewrite `build_prompt()` — that's the only thing you change
4. Run: `python step2_layout_gen/run_model.py --model qwen --prompt v5_myidea`
5. Compare output with previous versions in the viewer

**Rule: never edit `utils.py` or `run_model.py` between prompt experiments.**

## Why `resolve_overlaps()` was removed

**Old approach (wrong):** after the LLM placed elements, we sorted them by Y and pushed
overlapping elements down. This destroyed the LLM's semantic decisions — if the LLM put
an image at Y=0.20 because it's the most important element, and we pushed it to Y=0.45
because something else was there, we broke the intended visual hierarchy.

**New approach (correct):** the LLM is responsible for ALL positions. We only:
1. Clamp values outside [0,1] (crash prevention)
2. Re-inject truly missing elements (data completeness)

The prompts now explicitly instruct the LLM to choose positions that avoid overlaps.
If the LLM places two elements at the same Y, that is a prompt quality problem to fix
by improving the prompt — not a post-processing problem to fix with code.

## Technical knowledge

**`/no_think` prefix (Qwen-specific):** disables the internal chain-of-thought reasoning
that Qwen3 produces before answering. Without it, the model outputs hundreds of tokens
of `<think>...</think>` before the JSON. The prefix saves ~40% of generation time.
LLaVA does not support this — don't add it to LLaVA prompts.

**`importlib.util.spec_from_file_location`:** loads a Python file as a module dynamically.
This is how `run_model.py` loads any prompt file without importing it statically.
Pattern: `spec = spec_from_file_location("name", path)` → `module_from_spec(spec)` →
`spec.loader.exec_module(module)` → use `module.build_prompt()`.

**Output naming `{model}_{prompt}_{timestamp}.json`:** guarantees no overwrites.
Lets you compare outputs side by side in the viewer. The timestamp is `YYYYMMDD_HHMMSS`.

**`build_element_catalog()`:** generates a compact, human-readable summary of all elements
with their semantic hints (TITLE vs BODY, font size, bold). Passed to every prompt so the
LLM has a quick readable overview before the dense raw JSON. Helps smaller models (2B)
understand the content without having to parse the full JSON first.

## Prompt engineering principles used

**For 2B models (Qwen):**
- Short numbered lists outperform long paragraphs
- Give a readable catalog BEFORE the raw JSON
- `/no_think` saves tokens and time
- `temperature=0.0` for deterministic, reproducible results
- Retry prompt must be even shorter than the main prompt

**For vision models (LLaVA, Qwen-VL):**
- Images are passed in the `images` field of the message, not as base64 in the prompt
- Ask the model to describe what it sees before deciding placement
- Multimodal prompts work best when image description is explicitly requested

**General:**
- Prompts are hypotheses. Each version tests ONE new idea.
- Never combine multiple new ideas in one version — you won't know what worked.
- The `PROMPT_ID` string in each prompt file is for your logs and filenames.
